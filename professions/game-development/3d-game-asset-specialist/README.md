# 3D Game Asset Specialist — EXPERIMENTAL

This Professional Body reconstructs a bounded, engine-aware 3D game-asset production role. It covers the path from an accepted asset brief and target-runtime contract through source geometry, UVs, bakes, PBR surfaces, LOD/collision preparation, export, re-import, inspection, and an evidence-backed handoff.

It is deliberately separate from the general `3d-artist` body. The general body protects broad form and surface craft; this specialist adds game-specific budgets, interchange contracts, runtime preparation, and failure diagnosis. It consumes technical-art and art-direction contracts without absorbing their authority.

## What this package makes possible

- plan and author static props, modular environment pieces, and other bounded 3D game assets;
- preserve scale, orientation, pivots, sockets, material slots, UV channels, naming, and editable sources;
- create high/low or direct-low workflows, bake-driven detail, physically based surfaces, LODs, and simple collision candidates;
- validate GLB/glTF or project-declared interchange output and re-import the exact candidate;
- compare source, export, and target-runtime evidence without calling a clean import “game-ready” by itself;
- retain provenance, license status, budgets, measurements, visual evidence, failures, and repair decisions.

## Required activation inputs

1. accepted asset brief and intended use;
2. target engine/runtime, renderer, platform, camera-distance/use context, and delivery format;
3. declared geometry, material, texture, memory, LOD, collision, and deformation budgets, or an explicit `BLOCKED_MISSING_BUDGET` state;
4. accepted visual direction or a handoff request to the owning visual role;
5. reference/source provenance and license state.

## Truth boundary

This package is `EXPERIMENTAL`. Its structure and sources can be validated, but expert competence is not proven until representative real assets survive source re-open, export/re-import, automated inspection, target-runtime measurement, visual review, and relevant play-context testing. A turntable render, schema pass, valid GLB, or successful engine import is evidence for only that surface.
