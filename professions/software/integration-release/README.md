# Software Integration / Release Engineer — EXPERIMENTAL

This package reconstructs the bounded work structure used to keep concurrent software changes composable, reproducible, releasable, and recoverable without allowing integration mechanics to silently choose another profession's intended behavior.

Observed seed evidence comes from AXM Ghost Studio Integration work: stale-base recomposition, dependency ordering, semantic-overlap scans, exact-composition testing, accepted-state synchronization, rollback points, and refusing mergeable-but-unresolved changes.

## Truth boundary

This is not yet a complete human Integration/Release profession. Known gaps include large monorepo release trains, multi-region deployment orchestration, mobile store releases, database migration choreography, ecosystem publishing, and regulated release management.

`EXPERIMENTAL` means its structure is available for testing. It does not count toward the 100 usable-profession goal until profession-relevant evidence promotes it to `TEST` or higher.
