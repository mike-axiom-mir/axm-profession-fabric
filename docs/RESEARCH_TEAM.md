# Profession Fabric Research Team v0.1

This is the initial small team for compiling human professions into Professional Bodies.

The roles are deliberately about reconstructing **professional machinery**, not inventing agent personalities.

## 1. Profession Mapper

Protects fidelity to real human professional work.

Owns:
- observing and decomposing the profession;
- identifying actual tasks, signals, tools, decisions, outputs, handoffs, failure modes, and escalation paths;
- distinguishing widespread professional practice from one institution's habit;
- preserving disagreement between practitioners.

Must not:
- convert assumptions about a profession into facts without grounding;
- design the technical body implementation alone.

## 2. Deterministic Systems Architect

Protects explicit structure and reusable machinery.

Owns:
- turning mapped professional work into capabilities, procedures, state contracts, schemas, deterministic checks, and bounded interfaces;
- deciding where deterministic structure adds control/evidence;
- keeping contextual judgment explicit instead of disguising it as a fake rule.

Must not:
- replace profession evidence with architectural elegance.

## 3. Knowledge & Memory Architect

Protects source integrity and continuity.

Owns:
- knowledge domains and retrieval routes;
- source authority/versioning;
- canonical/project/working memory separation;
- retention and promotion rules;
- stale-knowledge detection;
- uncertainty and conflicting-source handling.

Must not:
- turn model recall into untracked professional canon.

## 4. Tool & Skill Engineer

Protects executable professional capability.

Owns:
- mapping work to existing tools;
- designing missing bounded tools/skills;
- tool permission and failure boundaries;
- reusable capability interfaces;
- ensuring professional capability is not trapped inside one model or one UI.

Must not:
- treat tool access as professional authority.

## 5. Professional QA / Adversary

Protects the difference between sounding professional and performing professional work.

Owns:
- representative fixtures;
- seeded failures;
- misleading/incomplete inputs;
- abstention/escalation tests;
- baseline comparisons;
- cross-intelligence portability tests;
- evidence audits and truth boundaries.

Must not:
- optimize tests merely to make the candidate body pass.

## Team interaction

The Profession Mapper supplies grounded work structure.

The Systems Architect compiles structure.

The Knowledge/Memory Architect supplies trustworthy continuity.

The Tool/Skill Engineer makes capability executable.

Professional QA attacks the result and returns failures to the correct layer.

No role is the constitutional merge gate. The AXM roots gate accepted Profession Fabric changes.

## First team objective

Do **not** attempt ten professions immediately.

First use one or two bounded professional slices to attack the v0.1 body contract. The early goal is to discover what the schema/spec is missing.

A strong first candidate should:
- have clear real-world workflows;
- have inspectable outputs;
- expose professional failure modes;
- use multiple tools/procedures;
- require handoffs or boundaries;
- allow objective fixtures without reducing the whole profession to a benchmark.

Ghost Studio's existing software/game specialists are useful seed observations, but Profession Fabric should eventually generalize beyond software production.
